## Changelog: correctness fixes (2026-09-14)

A multi-angle code review surfaced the following bugs, all now fixed and covered by `uv run pytest` (24 passed):

1. **Cross-symbol contamination in targets/sequences** — `model/targets.py::add_target`, `model/features.py::build_sequences`, and `model/sequence/patchtst.py::_targets_for_sequences` sorted by `date` only; on the multi-symbol `design_df`/`test_df` passed by `runner.py`, this let a horizon-ahead shift or a 60-day sequence window silently cross from one symbol into another at date boundaries. Fixed by sorting/grouping by `symbol` first everywhere the three functions touch a multi-symbol frame; `build_sequences` also now rejects any window whose first and last row don't share a symbol.
2. **`measure/jumps/naive.py` self-contaminated sigma** — the naive jump test estimated its own denominator via `np.std(r)` over the whole day, which includes the very jump being tested, letting a large enough jump inflate its own threshold and escape detection. Fixed to derive sigma from the jump-robust `robust` estimator (already excludes the jump by construction) instead: `sigma = sqrt(robust)`.
3. **`measure/panel.py` bypassed the `lm`/`lm_fdr` registry entries** — `build_symbol_design` hand-built `JumpVerdict` objects and called `_gumbel.critical_value` directly instead of dispatching through `JUMP_TESTS["lm"]`/`JUMP_TESTS["lm_fdr"]`, duplicating logic that could silently drift from the registered functions. Fixed: `_lm_day_stats` now also returns the per-day `local_sigma` slice it already computes, and `build_symbol_design` calls `JUMP_TESTS["lm"](r, rv, robust, local_sigma=...)` / `JUMP_TESTS["lm_fdr"](..., precomputed=...)` directly. (The `local_sigma_series`/`DayStat`/`lm_fdr_significance_series` imports at the top of `panel.py` remain — computing the trailing K/W-window statistics genuinely needs whole-history context the per-day `JumpTest` protocol can't express, which is the documented, intentional exception, not a further violation.)
4. **`evaluation/mcs.py::model_confidence_set` ignored forecast horizon** — always called `diebold_mariano` with the default `h=1`, under-correcting the HAC variance at `h=5`/`h=22` where overlapping targets (`targets.py`) induce real autocorrelation. Fixed: `model_confidence_set` takes a `horizon` parameter and forwards it as `h`; `results/tables.py::mcs_membership_table` passes its per-cell `horizon` through.
5. **`evaluation/losses.py::ranking_disagreement` was dead code** — defined but never called, so a real QLIKE-vs-MAE ranking disagreement was silently absent from output instead of flagged. Fixed: `results/tables.py::main_result_table` now computes a `ranking_disagreement` column per `(design_id, horizon, regime, jump_day)` cell.
   > Superseded: `main_result_table` no longer carries this column. A reversal is flagged only when Diebold-Mariano significant on both metrics, which needs the per-day series, so it lives in `evaluation/losses.py::ranking_disagreement_table`, written to `ranking_disagreement.csv` by `results/report.py`.
6. **`data/corporate.py::verify_split_adjustment` (the split-adjustment hard gate) was never called** in production, only in tests. Fixed: `build_panel.py::build_panel_for_symbol` now calls `fetch_corporate_actions` + `verify_split_adjustment` once per symbol; a real `UnadjustedDataError` propagates and stops the build, while a corporate-actions *fetch* failure (network/vendor) only warns and skips the gate for that symbol.
7. **`qa/checks.py` hard assertions were never invoked against the real built panel** — only exercised in tests. Fixed: `build_panel.py::main` now calls `assert_semivariance_identity` and `assert_min_intraday_obs` on the full assembled panel before writing parquet. `assert_no_split_date_unadjusted` was simplified to a no-arg audit-trail marker (it never inspected its former arguments — the real check is `corporate.verify_split_adjustment`).
8. **`.gitignore`'s bare `data/` pattern** matched at any depth, silently also ignoring `src/projekat/data/` (the real source package: `calendar.py`, `clean.py`, `corporate.py`, `vault.py`, `vix.py`), not just the intended repo-root cache directory. Fixed by anchoring it to `/data/`.
9. **`model/runner.py::run_one` dispatched to the sequence-model path via `model_name == "patchtst"`** instead of a protocol-level capability. Fixed: added `is_sequence_model: bool` to the `Model` protocol (`model/protocols.py`), set on every concrete model; `run_one` now checks `model.is_sequence_model`.
10. **`tests/test_gumbel.py` was stale** — it asserted the module's own superseded Revision-8 behavior (a `SIMULATED_CRITICAL_VALUES` table that was never implemented, per `_gumbel.py`'s Revision-9 docstring explaining why that comparison was flawed), causing `ImportError` at collection and aborting the entire test run. Fixed by rewriting the test file to verify the actual, documented closed-form Gumbel formula (`gumbel_c_and_s`/`critical_value`) instead of the abandoned table — including a rebuilt empirical-size check using `local_sigma_series` with a realistic fixed warm-up window (K=270), matching the module docstring's own verification methodology.

Two review findings were investigated and found to be **false positives**, not fixed:
- `_gumbel.py::critical_value`'s closed-form formula and `local_sigma_series`'s `(k-1)` divisor: the module's own Revision-9 docstring explains in detail why these are correct and why the earlier Revision-8 "simulated table" approach (which some reviewers assumed was still the intended design) was itself the bug. Only the stale test file needed fixing (item 10 above), not the implementation.

## Changelog: non-parametric back-transform + Mincer-Zarnowitz wiring (2026-09-14, later same day)

A second review pass against a stated invariant list (anchored walk-forward, validation-fold usage, back-transform formula, `depends_on`, direct point-in-time targets, seed ensembling, VaR/regime/QLIKE conventions) confirmed most invariants already held (anchored windows, `depends_on` on every model, VaR breaches against `r_d`, pooled VaR backtests, fixed regime boundary from window 1, QLIKE never applied to the jump series). Two real gaps were found and fixed:

1. **Back-transform correction used the Gaussian `0.5*sigma^2` formula instead of the required non-parametric `a = ln(mean(exp(residual)))`.** The Gaussian formula assumes log-residuals are normally distributed; RV residuals need not be, and using it systematically mis-corrects whenever the residual distribution is skewed or fat-tailed. Fixed: `model/backtransform.py::residual_correction` (renamed from `residual_variance`) now computes the non-parametric correction directly from out-of-fold validation residuals; `backtransform()` takes an additive `correction` term instead of `sigma2`. Every `FittedModel` implementer (`naive`, the OLS-family `_ols_base.py`, `lightgbm_model.py`, `xgboost_model.py`, `patchtst.py`) was updated to expose `backtransform_correction` instead of `sigma2`, computed the same way. Behavior for perfectly Gaussian residuals is nearly identical to the old formula (both estimate `E[exp(residual)]`); the difference only matters — and matters most — exactly where the module's own docstring says tree/sequence models produce non-Gaussian residuals.
2. **`ensemble_forecast`'s secondary seed-ensemble figure averaged `np.log(y_hat)`** — i.e., the log of the *already back-transformed* per-seed forecast, which equals `log_y_hat + backtransform_correction` and therefore baked each seed's own correction back in before averaging, double-counting it relative to a clean log-space average. Fixed: `run_one`/`_run_sequence_model` now also emit the raw `log_y_hat` and `backtransform_correction` columns; `ensemble_forecast` averages `log_y_hat` and `backtransform_correction` separately across seeds and calls `backtransform()` exactly once on the two means, matching the invariant that ensemble averaging happens "in log space, before back-transformation."
3. **Mincer-Zarnowitz (`evaluation/mincer_zarnowitz.py`) existed but had no caller anywhere** — the invariant that it be "a parallel secondary figure, coefficients from the validation fold only" was unmet because nothing computed those coefficients or attached a recalibrated QLIKE. Fixed by adding validation-fold plumbing: `runner.py::run_one`/`_run_sequence_model` now return `(test_rows, val_rows)` instead of a single frame (both carry a new `window_id` tag), and `run_all` returns `(test_results, val_results)`. `results/tables.py::attach_mz_recalibration(test_results, val_results)` fits MZ per `(model, design_id, horizon, window_id)` cell from `val_results` only, recalibrates test predictions (`y_hat_recalibrated = intercept + slope * y_hat`), and attaches `qlike_recalibrated` alongside the raw `qlike` column — `main_result_table` reports both side by side when present, never substituting one for the other. This is a signature-breaking change to `run_all`/`run_one` (tuple return instead of a single DataFrame); no other code in the repo called them yet, so nothing else needed updating.

## Changelog: WI-3/WI-4 econometric models — NNLS `har`/`log_har` split, `arfima`, `mem` (2026-09-15)

WI-3 (econometric models) and WI-5/WI-6 (LightGBM, PatchTST) were mostly already implemented from earlier sessions. One real gap in WI-3: the existing `har.py` was actually what the spec calls `log_har` (OLS in log space via `_ols_base.py::fit_ols`, back-transformed) — there was no separate NNLS-in-levels `har` and no `log_har` at all, so the "three deliberately distinct positivity mechanisms" requirement was unmet (only one of the three existed). WI-4 (`arfima`, `mem`) was entirely missing. Fixed:

1. **Split `har`/`log_har` into two permanently separate models.** The prior `har.py` (log+correction OLS) was renamed to `model/econometric/log_har.py`, registered as `"log_har"` — now explicitly documented as the headline benchmark for `relative_qlike`. A new `model/econometric/har.py` was built from scratch: NNLS (`scipy.optimize.nnls`) fit directly on **level** targets (`model/targets.py::LEVEL_TARGET_COL`, a new column added alongside the existing log `TARGET_COL`) over non-negative regressors (`RV_d/w/m`, already variances), guaranteeing a non-negative forecast by construction with no log transform and no back-transform correction.
2. **Added a `predicts_levels: bool` flag to the `Model`/`FittedModel` protocols** (`model/protocols.py`) for models whose positivity is structural rather than log+correction-based. `runner.py::run_one`/`_run_sequence_model` check this flag and skip `backtransform()` entirely for such models (their `predict()` already returns levels), writing `NaN` into the `log_y_hat`/`backtransform_correction` output columns rather than a value that would be misleading if read as log-space. Every existing model was updated to declare `predicts_levels = False` explicitly.
3. **Built `model/econometric/arfima.py` and `model/econometric/mem.py`** (WI-4), both `depends_on = {"grid"}`, both fit **independently per symbol** (unlike the cross-sectional HAR family) since a univariate long-memory/GARCH-style time series model can't be pooled across symbols:
   - `arfima`: local-Whittle estimate of the fractional-differencing parameter `d` (coarse grid search over the low-frequency periodogram), fractional differencing via the truncated binomial-series expansion of `(1-L)^d`, then `(p,q)` selected by BIC over `{0,1,2}^2` on the differenced series (`statsmodels.tsa.arima.model.ARIMA` with `d=0`). Forecasts are re-integrated back to levels via the inverse `(1-L)^-d` weights convolved against the training tail plus the forecast path — **not** anchored at "last level + a local delta" (an earlier draft of this that used that shortcut was numerically wrong by ~10 log-units on a smoke test, since `(1-L)^-d` is a long-memory operator whose reconstruction depends on the full differenced history, not just the most recent value).
   - `mem`: exponential-QML Multiplicative Error Model (Engle 2002), `mu_t = omega + alpha*RV_{t-1} + beta*mu_{t-1}`, fit by maximizing the exponential log-likelihood subject to `omega > 0, alpha >= 0, beta >= 0, alpha+beta < 1` (`scipy.optimize.minimize`, L-BFGS-B). Positivity is structural (a convex combination of non-negative terms), so `predicts_levels = True` and no correction is computed.
4. Updated stale docstrings: `evaluation/anova.py::decompose_variance_grid_only` now lists the correct current grid-only model set; `evaluation/losses.py::relative_qlike` now explicitly says the QLIKE baseline is `log_har`, not `har`.
5. Added `tests/test_runner.py`: every registered model (13 total) round-trips through `run_all` by name alone; `har`'s NNLS forecast is never negative and carries no back-transform correction; `log_har` does carry one; `collapse_seeds` is verified to be a true no-op (`assert_frame_equal` against the input) while `ensemble_forecast` collapses multiple seed rows into one and produces a different value than naively averaging the already-back-transformed forecasts — the two paths are structurally distinct (different output row counts) as WI-6 required, not just differently-valued.

Wall-clock check for WI-6 (PatchTST, as required before any further change to it): a single fit on a small synthetic panel took ~5.7s; scaling to the real grid (5 seeds x ~24 designs x 3 horizons x 11 windows ≈ 3,960 fits, with training-set size growing per window) was estimated at roughly 22-66 hours of sequential CPU wall-clock time. Left as-is per instruction — this is a compute-budget decision for whoever runs the full pipeline, not something to silently reduce in code.

## Changelog: first end-to-end run on real data (2026-09-19)

Ran the full chain (fetch → `build_panel` with all 36 designs → all 17 models via `scripts/run_econometric.py` → reports) on AAPL+BAC, windows 10-11. Every stage now completes; the following defects only showed up on real data and are fixed, each with a regression test:

1. **`data/clean.py::has_sufficient_coverage` measured both thresholds on the wrong resolution.** `clean_day` always receives 1m bars, but the count was compared against the grid's expected count and against `MIN_INTRADAY_OBS`. Result: 15m half days (14 returns) passed and `assert_min_intraday_obs` aborted the very first real panel build; and the 80% relative filter was a no-op on 5m/15m, so a data-hole day dropped at 1m survived at 5m/15m (grids with different day sets). Now: relative filter on 1m bars (same decision for every grid), absolute floor on the number of returns the grid actually yields (`_n_grid_returns`, verified equal to `len(log_returns(resample_day(...)))` on all 12,069 AAPL day×grid cases). (`tests/test_clean_coverage.py`)
2. **`results/tables.py::attach_losses` kept the last h days (no realized target)**, turning numpy RMSE/MAE for whole cells into NaN. Rows with NaN `y_true` are now dropped before scoring.
3. **`evaluation/var.py::kupiec_test` returned LR=0, p=1 for zero breaches** — an over-conservative VaR reported as perfect (9 of 492 real cells). Now uses `xlogy` (0·log 0 = 0). `dynamic_quantile_test` returns NaN instead of a negative F when the regression is rank-deficient (no breach variation). (`tests/test_var_edge_cases.py`)
4. **Seeds were never collapsed in the report path** (`runner.collapse_seeds` is a documented no-op): PatchTST reached the ANOVA/VaR/n_obs as 5 rows per day. `tables.py::collapse_seed_losses` (C3 primary: mean of per-seed losses, one row per forecast key) now runs in `build_all_reports` right after MZ; `main_result_table` computes RMSE/MAE from the per-row loss columns.
5. **DM/MCS/ranking compared models only within a `design_id`, but grid-only models (incl. the `log_har` baseline) exist only on their representative design** — so 33 of 36 designs had no baseline comparison (90 DM rows instead of 1,092). `report.py::_broadcast_grid_only` replicates grid-only rows onto every design of their grid for these comparisons only (valid: `y_true` verified identical across designs of a grid) — **never for the ANOVA**, where the copies would be duplicated non-independent rows.
6. **`mcs_membership_table` built loss series positionally**, not aligned by (date, symbol). Now pivots and aligns like `dm_against_baseline`. (`tests/test_report_alignment.py` covers 4-6.)

Also added: `scripts/run_report.py` (the only caller of `build_all_reports` on a run directory — rebuilds the index first, so several `run_econometric.py` processes may write into one run dir in parallel), and a parallel, quota-aware `scripts/fetch_data.py` (export `job_id`s persisted under `data/raw/1m/.jobs`, per-chunk temp dirs so two chunks of one symbol never share a `.part`).

**Open scale issues (not yet addressed):** PatchTST at full scale is ~300 serial CPU-hours (5,940 fits; torch is the CPU build); `build_all_reports` holds everything in memory — 2.9 GB peak for 0.5M test rows, so the full ~100M-row run will not fit in 64 GB without per-horizon streaming and a chunked Type III ANOVA.

## Changelog: validation scheme replaced; measurement and model revisions (2026-09-19, evening)

A review of the thesis against the code found defects that the old scheme could not be patched around, so the validation scheme was **replaced**, not amended. `uv run pytest`: 219 passed. The panel was rebuilt into `data/processed/v2/`; the old `results/run_main` (11-window scheme) is obsolete.

Measurement layer:
1. **ln(J) with an epsilon** — HAR-J, the tree union and the PatchTST channel used `ln(max(J, 1e-12))`, i.e. -27.6 on every non-jump day, so the J coefficient mixed jump occurrence with jump size and depended on the epsilon. Now `ln(1 + J)` everywhere (`features.log1p_jump`), 0 exactly when J = 0.
2. **BNS theta was BPV's for every estimator** — the asymptotic-variance constant is estimator-specific. Each estimator now declares `bns_theta` in its own file (bpv/trbpv 0.609, medrv 0.96); `panel.py` passes `estimator=` to every jump test and `bns.py` reads the constant from the registry.
3. **Significance levels pinned in config**: BNS alpha 0.001 one-sided, LM Gumbel at 0.999, LM-FDR BH q = 0.05 with the Gumbel day p-value. Measured consequence (AAPL+BAC): LM-FDR now flags MORE days than LM (5m 37.8% vs 19.4%) — with ~19% of days below p = 0.001, the BH threshold at q = 0.05 rises to ~0.02. At 0.999 the closed-form Gumbel value is flat (~6.02) for n ~ 24-34.
4. **15m dropped half days that 1m/5m kept** — early closes are now dropped from every grid, and the day-keep decision checks the floor on every configured grid, so the three grids share one day set by construction. Every exclusion carries a reason; `build_panel` writes `<stem>_exclusions.parquet`, `<stem>_corporate.csv` and `<stem>_diagnostics.csv` (`qa/panel_diagnostics.py`).
5. `local_sigma_series` and `_lm_day_stats` vectorized (the per-day mask over every 1m return was O(days x returns)); raw bars are loaded once per symbol instead of once per grid. Full 36-design build: ~40 s per symbol.

Validation scheme (`model/windows.py` deleted, `model/walkforward.py` added):
6. **MEM, ARFIMA and every TTM model produced ONE forecast per symbol for a whole test year**, from the state at the end of the fitting span (one year before the test year, because the validation fold sat in between). Now every model forecasts every day with inputs/state updated daily (MEM recursion rolled through every day, ARFIMA filtered with d/ARMA fixed between refits and re-integrated over the full history, TTM context = the 512 days ending at t, PatchTST sequence ending at t).
7. Expanding window from 2010-01-01; every trained model re-estimated every 21 trading days on all rows strictly before the refit date whose target is also realized before it (PatchTST: retrained from scratch yearly, 3 seeds, early stopping on the last 10% of training dates with purged targets, ln(1+J) channel standardized on training data).
8. **The validation fold is gone.** The back-transform correction and Mincer-Zarnowitz coefficients for day t come from the model's own out-of-sample errors realized in the trailing 252 trading days strictly before t (`backtransform.trailing_corrections`, `trailing_mincer_zarnowitz`). 2014 is a warm-up year (forecasts produced, `is_warmup`, never evaluated); evaluation is 2015-2025.
9. Combined forecasts (`ttm_c_plus_j`, `log_har_ttm`): m* = sum(y)/sum(y_hat) (ratio of sums), not the mean of ratios.
10. HARQ: standardized sqrt(RQ) x ln(RV_d) (was RV_d x sqrt(RQ) in levels inside a log regression, ~1e-8, i.e. HARQ was effectively log-HAR). ARFIMA local-Whittle bandwidth n^0.65 (was n/4).

Evaluation:
11. **VaR compared the forecast for t+1 with the return of day t**, already known and whose RV was a model input. Now h = 1 only, against `r_d_next` (the same symbol's next session), Christoffersen/DQ never across symbol boundaries.
12. **Regime labels depended on the grid** (each row's own RV_m, noise-inflated at 1m), leaking A1 variance into the regime factor. Now one label per (symbol, date) from 5m RV_m against the median of the first training period, identical for every design (`regime_labels.parquet` in the run dir).
13. The ANOVA docstring and CLAUDE.md said grid-only rows are duplicated across the 12 estimator x jump_test combinations in the ANOVA; they never were (`_split_by_dependence` gives two disjoint sets). Corrected. Block bootstrap block length max(h, 5). H5 placebo: 100 permutations within symbol (J_w/J_m/C_w/C_m recomputed from the permuted J_d -- the old version permuted them independently), real dQLIKE vs log_har against the permutation distribution. H4: Kendall tau between QLIKE and Lopez rankings. Contamination counted in trading days (2,264 of 2,766, 81.9%). `run_report.py` crashed on an empty per-horizon CSV.

## Changelog: first full run on the new scheme, and what it exposed (2026-09-20)

The chain ran end to end on 29 symbols (`data/processed/v2`, `results/run_v2`): panel 4,164,084 rows in ~19 min, 246/246 combinations in 2.5 h on 18 shards with zero failures, report 6.7 h, diagnostics 22 min. Three defects surfaced only at that scale, all now fixed (`uv run pytest`: 222 passed).

1. **NVDA's back-adjusted prices are quantized, and one symbol owned the whole evaluation.** NVDA is priced at ~0.46 USD in 2014-2016 after back-adjusting the 4:1 (2021) and 10:1 (2024) splits, rounded to the cent: an effective tick of ~2.2%. Consequences measured on the built panel and the finished report: the only 65 days in the panel with `RV_d = 0` (a 15m day whose price never moves), a median RV(1m)/RV(5m) of 2.2-2.5 for 2014-2016 against 1.14 panel-wide, and **99.77% of the total QLIKE mass** in evaluation — the naive model's mean QLIKE was 14,161 with NVDA and 2.32 without, and the raw-QLIKE ANOVA collapsed to ~0 for every factor because the error term was all NVDA. Fixed by excluding NVDA in `config.EXCLUDED_SYMBOLS` (28 symbols), exactly as MT was excluded earlier, and by adding the two signals that make this visible at build time to `qa/panel_diagnostics.py`: `zero_rv_days` and `rv_ratio_1m_over_5m`. Without NVDA the remaining 81 extreme symbol-days (AMD 2015, QCOM 2019) carry 1.6% of the mass and change no ranking -- genuine volatility events, not a data defect.
2. **QLIKE was allowed to be inf.** A row with `y_true = 0` (the zero-variance days above) or a forecast that is NaN, zero or inf has no QLIKE. Such rows previously flowed into every mean, and `mincer_zarnowitz_table` crashed on them (`exog contains inf or nans`), killing the whole report after h = 1. Fixed: `results/tables.py::unscoreable_rows_table` counts them per (model, design, horizon, reason) into `unscoreable_rows.csv` and `attach_losses` scores only the rest. Measured on the v2 run: 3,034 `zero_target` and 126 `non_positive_or_infinite_forecast` rows out of 19.5M at h = 1.
3. **ARFIMA overflowed on 126 rows.** Its innovations come from inverting the MA polynomial, which with a near-unit MA root amplifies over thousands of observations; the re-integrated log forecast reached +55,848, i.e. `exp()` = inf. Affected NVDA and ORCL only. Fixed with a numerical guard: a log forecast more than 10 outside the observed range is NaN (a recorded missing forecast), never an inf.
4. `evaluation/diagnostics.py::_eval_qlike` did not apply the scoreable filter, so one zero-variance day turned every H5 permutation mean into NaN and the placebo into a constant p-value of 0.0099. Fixed to use `tables._scoreable`.
5. Added `--exclude-symbols` to `scripts/run_report.py` and `scripts/run_diagnostics.py` (recorded in `excluded_symbols.json`) as the stopgap for a symbol excluded after its forecasts exist; the clean path is a rebuild, because the cross-sectional models are fitted across symbols.

**Measured, for the thesis text:** panel diagnostics say the three grids keep an identical day set for every symbol (3,986-3,989 days), 0 of 29 corporate-action checks were skipped, and days were excluded as 986 half days, 1,350 vendor bars on non-sessions and 12 for insufficient 1m coverage. Jump-day shares on the full panel (bns / lm / lm_fdr / naive): 5m+bpv 5.6% / 20.2% / 39.0% / 0.2%. **LM-FDR is now more liberal than LM**, the opposite of the earlier assumption: BH at q = 0.05 over a window where ~19% of days sit below p = 0.001 raises the threshold to ~0.02. TrBPV+BNS at 1m flags ~80% of days. TTM contamination: 2,264 of 2,766 evaluation trading days (81.9%). Packages: numpy 2.5.3, pandas 2.3.3, statsmodels 0.15.0, scipy 1.18.1, pyarrow 25.0.1, lightgbm 4.7.0, xgboost 3.4.1, torch 2.11.0+cu128.
